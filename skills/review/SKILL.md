# review — 回顧

兩種粒度。都只用**已經在手的材料**（`Sessionlog/`、`HUB.md`、`北極星.md`），不另外問他問題。

## 日回顧

排程範本「日 review」每日 22:00 跑（排在「筆記整理」之後）。

1. 讀當日的 `Sessionlog/*.md`。
2. 還原 **Worklog**：今天實際動了什麼。一行一件，附出處檔名。
   ⛔ 不要寫「討論了 X」這種沒有結果的條目——要寫「做了什麼、產出在哪」。
3. 列 **未解決清單**：講過但沒收尾的。每條註明卡在哪（等他決定／等外部／單純沒做完）。
4. 寫進當日的 Daily Note（`Doc/Daily/YYYY-MM-DD.md`），餵給隔天的晨報。
5. 未解決清單裡，有哪條其實是 `HUB.md` 某條主線的「下一步」→ 回寫過去。

## 週回顧

排程範本「週回顧」每週日 22:30 跑，產 `Doc/週回顧 YYYY-Wnn.md`。

四個部分，缺材料的那部分就老實寫「這週材料不足」，不要硬湊：

1. **使用模式深度分析** — 這週他最常叫誰做事、最常卡在哪、哪類請求重複出現。
   同一個意圖出現第三次 → 接到下一項。
2. **工具化提案** — 把重複的動作提成「要不要變成固定流程」。
   落點是能力或排程，判準與出處格式照 `skills/sessionlog` §足跡掃描。一條一條讓他勾。
3. **HUB 體檢** — 每條主線：這週有動嗎？逾期幾天？「下一步」還成立嗎？
   沒動超過兩週的，問他是不是其實已經停了。
4. **北極星對照** — 每顆目標：這週哪裡有進展（附查得到的識別值）、哪裡還缺一塊、
   要不要叫哪位員工去補。進度格附不出證據就寫「還沒驗證」，⛔ 不准代填數字。

收尾一句：下週最該先動的是哪一件，為什麼。
